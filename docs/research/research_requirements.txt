============================================================
SECTION 1 — NON-NEGOTIABLE RESEARCH RULES
============================================================

以下為不可違反的研究原則。

RULE 1

RL 必須是主要的 Mapping Search Controller。

RL Agent 必須負責：

- 選擇修改目標
- 選擇修改範圍
- 選擇 Action 類型
- 選擇 Action 參數

不得表面使用 RL，
但讓外部 Greedy、Beam Search 或其他 Optimizer
實際決定最終修改方案。

允許 deterministic compiler 與合法性檢查。

允許產生合法候選集合。

但候選生成器不能利用未揭露的完整 PPA Oracle
預先挑選最佳 Action。

若候選集合必須截斷，
截斷策略、計算成本與可能引入的搜尋偏差
都必須記錄。

RULE 2

新研究不得直接沿用 Gemini OP1–OP5
並更改名稱宣稱為原創演算法。

不得讓 V2 的主要搜尋流程依賴：

hybrid/actions.py
hybrid/search.py

也不能依賴原本 INDM 專屬的
Cluster / Multi-Ring Architecture Search。

但允許保留這些模組作為 Legacy Baseline。

RULE 3

RapidChiplet 是外部 Chiplet 評估基礎。

但 RapidChiplet 不提供完整 DNN E2E Inference Oracle。

新研究需要自行定義、實作及驗證：

- DNN Operation Semantics
- Tile Mapping Semantics
- Compute Service Model
- Memory Service Model
- Resource-Constrained Scheduler
- E2E Energy Accounting

不得將 RapidChiplet 的互連平均延遲
直接宣稱為 DNN E2E Latency。

RULE 4

所有物理參數必須具有來源。

允許使用：

- 文獻參考參數
- 經驗性探索假設
- 經校準的實測參數

但必須明確區分三者。

禁止憑空宣稱：

- ASIC accuracy
- Silicon-verified PPA
- Signoff timing
- Foundry-calibrated area
- Real hardware power

RULE 5

不得偽造：

- 訓練結果
- Benchmark
- PPA
- Seed 統計
- Confidence interval
- 研究文獻
- 實驗成功紀錄

任何未執行的測試標記為 NOT RUN。

任何無法確認的功能標記為 UNVERIFIED。

任何缺少必要依賴的實驗標記為 BLOCKED。

RULE 6

保留所有 Legacy 原始碼與既有測試。

新演算法必須使用獨立研究模組。

建議位置：

simplified_rapidchiplet/
    simple_rapidchiplet/
        rapid_rl_v2/

不得直接覆蓋 Legacy Baseline。

RULE 7

所有研究主張必須可透過實驗否定。

不得先預設 RACE-RL 一定優於其他演算法。

不得使用測試資料反覆調整方法後，
仍將該測試集稱為獨立驗證。

PHASE 1 — RESEARCH PROBLEM FORMULATION
============================================================

本研究採用：

Fixed-Hardware DNN Mapping Optimization.

輸入：

W = DNN Workload
H = Fixed Chiplet Hardware
M0 = Initial Feasible Mapping
B = Physical Oracle Evaluation Budget
p = User Preference / Constraints

輸出：

M_best = Best Oracle-Validated Feasible Mapping

-----------------------------------
1. DNN Representation
-----------------------------------

定義：

G_D = (V_D, E_D)

其中：

V_D = DNN Operators
E_D = Tensor Dependencies

必須支援正確的：

- Operator Shape
- Tensor Shape
- Tensor Dependency
- Residual Connection
- Branch / Merge
- Tensor Lifetime

第一階段至少支援：

Conv
Elementwise Add
Pooling
Linear

其他 Operator 必須明示支援範圍。

不支援的 Operator 不能默默忽略。

-----------------------------------
2. Tile Representation
-----------------------------------

建立：

TileIR

對每個 Layer l：

T_l = {T_l,1, ..., T_l,n}

必須保證：

Union(OutputRegion(T_l,k)) = Output(l)

且：

OutputRegion(T_l,i)
INTERSECT
OutputRegion(T_l,j) = Empty

for i != j.

也就是：

每個 Output Element 必須被正確產生一次。

Convolution 允許 Input Halo 重疊。

不得因此錯誤計算 Output Ownership。

如果使用 Channel Reduction Split，
必須明確模擬 Partial-Sum Reduction。

否則第一階段禁止這種 Split。

-----------------------------------
3. Hardware Representation
-----------------------------------

定義：

G_H = (V_H, E_H)

V_H：

- Compute Chiplets
- Memory Chiplets
- IO Chiplets

E_H：

- Physical Links

每個 Hardware Node 定義：

Compute Capability
Memory Capacity
Memory Bandwidth
Compute Slots
Clock
Static Power
Area
Physical Placement

每個 Link 定義：

Bandwidth
Propagation Delay
Endpoint
Routing
PHY Limit
Energy Coefficient

所有單位必須明確。

不可固定依賴 INDM 的：

Compute Cluster <= 4
Multi-Ring
Specific IO Mesh

但可以將舊架構當作其中一組實驗硬體。

-----------------------------------
4. Mapping Representation
-----------------------------------

定義：

M = (T, μ, σ, ρ)

T = Tile Partition

μ = Tile-to-Hardware Placement

σ = Tensor Storage / Residency

ρ = Tensor Communication Routing

如果 Routing Algorithm 固定：

ρ 必須由 Hardware、Placement、
Memory Endpoint 和 Routing Rule 推導。

不能讓 Actor 任意指定不存在的路徑。

-----------------------------------
5. Objective
-----------------------------------

第一階段以 EDP 為主要目標。

EDP(M,H) = E(M,H) × D(M,H)

使用共同的固定參考尺度：

J(M,H) =
    [E(M,H) / E_ref]
    ×
    [D(M,H) / D_ref]

E_ref、D_ref 必須在同一比較任務內固定。

不能每個 Candidate 都重新定義 Reference。

如果進行不同 Hardware Context 的比較，
必須說明跨硬體共同尺度。

因為第一階段固定 H：

Area(H) 是常數。

因此 Area 不需要作為內層 Mapping Reward
的可變最佳化目標。

Area 仍須報告，
也可以作為明示的可行性限制。

Power 必須區分：

Average Inference Power = Energy / Makespan

與：

Peak Power
TDP

不可混用。

-----------------------------------
6. Optimization Target
-----------------------------------

令：

J*_t =
    minimum J among feasible designs
    evaluated by the official analytical oracle
    up to step t.

研究目標：

maximize E[
    log(J*_0 / J*_B)
]

這代表：

在固定 Oracle Budget 下，
最大化相對於初始設計的最佳搜尋改善。

Oracle-Validated 不代表 Silicon-Validated。

-----------------------------------
7. Feasibility
-----------------------------------

至少包括：

- Output Coverage
- Operator Semantics
- DAG Dependencies
- Legal Placement
- Memory Capacity
- Buffer Lifetime
- Compute Slot Exclusivity
- Link Connectivity
- Transfer Scheduling
- Resource Conflicts

Strict PPA Limits 必須與 Physical Feasibility 分開。

若 Initial Mapping 不符合嚴格限制，
不能默默將其當成可行起點。

可以：

A. 要求可行初始設計

或

B. 另外定義 Constrained Search Protocol

但不得混合兩種評估設定而不揭露。

輸出：

docs/race_rl_v2/01_constraints.md
docs/race_rl_v2/01_research_hypotheses.md

PHASE 4 — CONTRIBUTION 2: COUPLED ACTION
============================================================

研究假說 H2：

Dependency-coupled atomic edits may overcome
budget-limited combinatorial search barriers
more efficiently than independent local edits.

不要聲稱單點動作永遠無法到達相同 Mapping。

如果允許接受較差中間狀態，
單點搜尋可能仍可到達。

真正要研究的是：

有限 Oracle Budget 下的搜尋效率。

-----------------------------------
1. Action Definition
-----------------------------------

a_t = (S_t, τ_t, δ_t)

S_t = Selected Dependency Subgraph

τ_t = Transaction Type

δ_t = Transaction Parameters

三者必須由同一個 RL Policy 決定。

-----------------------------------
2. Action A1: Cut-Migrate
-----------------------------------

選擇一組相關 Tiles。

同時修改：

- Tile Placement
- Related Tensor Routes
- Resource Allocation
- Required Communication

所有修改必須 Atomic Commit。

-----------------------------------
3. Action A2: Work-Share Rewire
-----------------------------------

對相依 Layers 同時修改：

- Tile Partition
- Work Distribution
- Core Assignment
- Producer-Consumer Connections

必須重新計算：

Output Coverage
Input Region
Convolution Halo
Communication Traffic
Memory Lifetime

不能只修改 Core 數量，
卻保留舊的 Tensor Traffic。

-----------------------------------
4. Action A3: Memory-Affinity Exchange
-----------------------------------

聯合修改：

- Tensor Storage Endpoint

- Consumer Placement
- Communication Demand

必須驗證：

Memory Capacity
Tensor Lifetime
Routing Feasibility
Resource Conflict

-----------------------------------
5. Action Selection
-----------------------------------

使用 Autoregressive Policy。

Step 1:

Select Root / Subgraph

Step 2:

Select Action Type

Step 3:

Select Parameters

整體：

π(a|o) =
    π(S|o)
    × π(τ|o,S)
    × π(δ|o,S,τ)

三階段合起來是一個 Environment Step。

不是三個獨立 RL Time Steps。

-----------------------------------
6. Subgraph Generation
-----------------------------------

避免枚舉所有可能子圖。

先由 Actor 選 Root Tile。

再沿合法 Dependency Edge 逐步擴展。

可測試：

K = 2

============================================================
PHASE 5 — CONTRIBUTION 3: REWARD
============================================================

研究假說 H3：

A verified-best objective combined with
schedule-informed potential shaping may improve
credit assignment and learning efficiency.

Potential-Based Reward Shaping 本身不是新發明。

不可將既有數學公式宣稱為原創。

-----------------------------------
1. Verified Archive
-----------------------------------

定義：

J*_t =
    min J(M_i)

其中 M_i 必須是：

- Structurally Legal
- Oracle Evaluated
- Feasible

未完成正式評估的 Candidate
不能更新 Best Verified Archive。

-----------------------------------
2. Terminal Base Reward
-----------------------------------

對有限 Episode：

r_base(t) = 0

當 t 不是 Terminal。

Terminal 時：

r_base(T) =
    log(J*_0 / J*_T)

如果 Episode 因 Budget Exhaustion、
No Legal Action 或其他明示條件結束，
必須正確處理 Terminal Return。

-----------------------------------
3. Schedule-Informed Potential
-----------------------------------

定義：

Phi(s) =
    lambda_b * log(J*_0 / J*(s))
    -
    lambda_c * BottleneckProxy(s)

其中：

BottleneckProxy(s)
必須來自可追溯 Scheduler Diagnostics。

不得任意使用：

Total Link Utilization
Total Traffic
Core Utilization

作為真實 EDP 改善的替代目標。

lambda_b、lambda_c
必須透過 Validation Experiments 決定。

不能在 Test Set 上調整。

-----------------------------------
4. Potential-Based Reward Shaping
-----------------------------------

r_shaped(t) =
    r_base(t)
    +
    gamma * Phi(s_next)
    -
    Phi(s_current)

第一版研究設定：

gamma = 1

PPO 使用相同 gamma。

Terminal State：

Phi(terminal) = 0

必須驗證：

Sum(rewards over episode)
=
log(J*_0 / J*_T)
-
Phi(s_0)

這個等式需要對不同 Action Sequence、
Episode Length、Invalid Candidate、
Cache Hit 和 Termination Case 驗證。

若使用不同 Discount Factor
或不一致的 Terminal Handling，
不能再宣稱保持相同的最適策略。

-----------------------------------
5. Dense Improvement Baseline
-----------------------------------

另建立：

r_dense(t) =
    log(J*_t / J*_(t+1))

在 gamma=1、正確邊界條件下：

Sum(r_dense)
=
log(J*_0 / J*_T)

這是重要對照。

因為 Dense Improvement 本身
就能提供中間學習訊號，
且與終點搜尋改善精確對應。

必須比較它與 Bottleneck Shaping，
不能預設複雜 Reward 一定較好。

-----------------------------------
6. Invalid Candidate
-----------------------------------

結構非法 Action
優先由 Action Mask 排除。

物理不可行候選
依事先定義計入 Oracle Budget。

主 Reward 不任意加入：

-2
-5
-10

等固定懲罰。

若加入額外 Penalty，
應視為另一種 Reward Variant。

必須獨立進行 Ablation。

-----------------------------------
7. Reward Ablation
-----------------------------------

至少比較：

R1. Dense Best-Improvement

R2. Best-So-Far Potential

R3. Best + Schedule Potential

R4. Schedule Potential
    without Physical Criticality

量測：

Convergence
Reward Variance
Best EDP
Oracle Efficiency
Training Stability
Wall Time

PHASE 5 GATE：

Reward Invariance / Telescoping Tests
必須通過。

不可用 Reward 曲線增加
代替真實 EDP 改善。
